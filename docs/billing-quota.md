# 计费与额度

DouDi 的实际扣费以控制台价格页、模型配置、分组倍率和请求日志为准。文档只解释如何读懂这些信息。

## 先看三层价格

| 层级 | 作用 |
| --- | --- |
| 模型价格 | 模型本身的输入、输出、图片、音频或固定消耗规则 |
| 分组倍率 | 不同线路或账户组对模型价格的倍率影响 |
| Key 或账户限制 | 单个 Key、账户余额、套餐额度和并发限制 |

一次请求最终消耗通常由模型价格和分组策略共同决定。图片、音频、多模态和长上下文模型可能有额外计费项。

## 如何估算成本

1. 在价格页找到目标模型。
2. 确认你的 Key 使用哪个分组。
3. 查看是否存在固定消耗、缓存计费、图片计费或阶梯计费。
4. 用小请求先跑一轮，在请求日志里核对实际扣费。
5. 批量接入前做并发和长上下文样本测试。

## 余额不足怎么办

优先检查：

- 账户余额是否足够。
- 套餐额度是否已经用完。
- Key 是否设置了单独额度。
- 请求是否选择了高倍率分组。
- 是否调用了固定消耗较高的图片或多模态模型。

## 下游接入建议

下游生产服务不要只按单次样例估价。建议至少准备三类样本：

| 样本 | 用途 |
| --- | --- |
| 短文本 | 验证基础连通和最小消耗 |
| 长上下文 | 验证真实 token 成本 |
| 峰值并发 | 验证线路容量和限速 |

完成样本后，再确定模型白名单、Key 额度、分组策略和告警阈值。
